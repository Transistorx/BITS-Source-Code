# Design: per-frame weight over MQTT, runtime broker config, server WebSocket live path

Date 2026-10-09. Class C. Hazards: docs/superpowers/specs/2026-10-09-weight-mqtt-ws-hazards.md (HZ-01..21), index specs/hazards.md. Standards: .claude/team/FW_STANDARDS.md. The ESP32 is not a certified safety device; nothing here protects the process (HZ-21). Paths are repo-relative; [S] = server (Python), [C] = firmware (C). Signatures only.

## 1. Goal, non-goals, coverage
Goal: publish every CAS frame on cas/{dev}/telemetry/weight with honest freshness, keep inbound ZERO/TARE deliverable under load, make broker credentials runtime-configurable without bricking, and give the browser a WS live path that can issue ZERO/TARE with one id authority.
Non-goals: scale input (CH1/UART1, parsers), weight/ctl semantics, the indicator transmit path (encoder stays NOT_VERIFIED, scale_cmd_encode.c:10-18, remote_cmd.c:108), TWDT, flash encryption, pump control.
Covered: REQ-WMQ-01..52 (sections below); 53, 54, 55 recorded as constraints only (section 8).

## 3. State machines
Weight publish (weight_tx task, mqtt_link_weight_frame): IDLE -(REAL sample, new cas_seq)-> PUBLISH ctl+tel, hb timer reset -(REAL, same cas_seq, hb due)-> HEARTBEAT tel only -(weight_source not REAL)-> SILENT (no call, nothing published; server marks invalid at age > 3000 ms). Entry to SILENT is implicit through weight_source STALE/OFFLINE (3000/10000 ms, weight_source.h:28-37); exit on the next REAL sample. Safe state: SILENT. Reason codes in status: scale_state (WAITING/ONLINE/STALE/OFFLINE).
MQTT link (mqtt_pub task, unchanged shape mqtt_link.c:264-323): CONFIG_RESOLVE -> {OFF(reason MQTT_CFG_EMPTY|MQTT_CFG_INVALID|MQTT_INIT_FAIL), CONNECTING} -> CONNECTED <-> BACKOFF(1-30 s jitter). OFF is a degraded state logged once with reason; boot, Wi-Fi, weight WS and portal are unaffected (REQ-WMQ-24). Supervision: HB_FROZEN_MQTT_PUB 10 s logs; 30 s -> mqtt_link_stop/start; second within 10 min -> esp_restart logged with reason (REQ-WMQ-52).
Command in flight (server LiveHub, per (device, channel)): FREE -(cmd accepted, row created, published)-> IN_FLIGHT(client_deadline 3 s, lock_deadline 6 s) -(ack)-> FREE + cmd_ack(late = after client_deadline) -(client_deadline)-> UNKNOWN (cmd_state unknown; lock held) -(ack before lock_deadline)-> FREE + cmd_ack late=true -(lock_deadline)-> FREE + cmd_state lock_released -(birth new boot_id)-> FREE + cmd_state rebooted -(bridge disconnect)-> FREE + cmd_state link_lost within 1 s. Refusals never leave FREE: not CONNECTED, no auth, not whitelisted, bad cmd/channel, rate limit, busy channel, DB error. Ack for an unknown id: counted, dropped.
Device command (unchanged scale_cmd.c:217-309, 335-384): parse -> dedupe -> validate (adds ttl <= 10000, rate 2 s) -> queued -> execute -> ack FAILED/UNVERIFIED while encoder unverified.

## 6. Persistence and compatibility
- NVS key "mqtt_cfg", blob, BROKER_CFG_VERSION 1, magic + crc32. Corrupt, absent, wrong version, failed crc or invalid URI -> Kconfig values, logged with the broker_cfg_src_t reason; the key is left in place for inspection and overwritten on next save. Wi-Fi keys are untouched (nvs_config.c:49-59 wholesale erase is unchanged and out of scope). Migration: none needed (new key). A later version writes a new record under the same key with version 2; decode rejects unknown versions to Kconfig.
- OTA/rollback: units running the old image keep Kconfig only; the new image reads the key if present. Rolling back to an old image ignores the blob (harmless). No partition table change. telemetry/weight stays schema_version 1 and the server accepts both the old (src_uart only) and new (channel) bodies, so mixed fleets work.
- Risk record: broker password is plaintext in NVS; flash encryption and secure boot are not enabled (no FLASH_ENC/SECURE_BOOT in the tree) and are NOT enabled by this change (FW_STANDARDS 4). TWDT is not configured and no task subscribes; not added here.
